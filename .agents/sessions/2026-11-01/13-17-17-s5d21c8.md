别慌，这段 Java 在 C 里就是三十行。我先把等价的 C 写出来，你就知道每个花括号在干什么。

```c
#include <stdio.h>
#include <stdbool.h>

typedef struct {
    int total;
    int available;
    int frozen;
    int used;
} Budget;

bool check(Budget *b) {
    return b->total == b->available + b->frozen + b->used;
}

int main(void) {
    Budget b = {1000, 1000, 0, 0};
    printf("%d/%d/%d\n", b.available, b.frozen, b.used);
    printf("守恒: %d\n", check(&b));
    return 0;
}
```

对应关系：

| Java | C 里对应 |
|---|---|
| `public class Budget { ... }` | `typedef struct { ... } Budget;` 再加属于它的函数 |
| `int total = 1000;` | struct 成员，顺带初始化 |
| `boolean check()` | `bool check(Budget *self)`，`self` 被藏起来了 |
| 方法里直接写 `available` | `self->available` |
| `Budget b = new Budget();` | `Budget *b = malloc(...)` 并把字段初始化 |
| `b.available` | `b->available` |
| `System.out.println(x)` | `printf("%d\n", x)` |
| `public static void main(String[] args)` | `int main(void)` |
| `"守恒: " + b.check()` | 字符串拼接，`+` 会自动把布尔值变成 "true" |

三个可能卡住的点：

1. 花括号嵌套。最外层 `class Budget { }` 是"地盘"，里面只能放字段和方法，不能放普通语句；能放普通语句的只有 `main` 里面。
2. `static`。`main` 是程序入口，启动时还没有任何对象，所以它不能依赖对象，必须是 `static`。C 的 `main` 也没有 self，一个道理。
3. 为什么不是 `if`。其实可以是。`return 表达式;` 和 `if (表达式) return true; else return false;` 完全等价，Java 习惯写前者。

```java
boolean check() {

}
```

| 行 | 代码 | 在干什么 |
|---|---|---|
| 1 | `public class Budget {` | 开始定义一张叫 Budget 的表；`{` 到最后的 `}` 之间都是它的内容 |
| 2 | `int total = 1000;` | 开一栏叫 total，整数，初始填 1000 |

| 6 | `boolean check() {` | 定义一个操作叫 check，交回真假；括号空着表示不需要额外信息 |
| 7 | `// ...` | 注释，不执行 |
| 8 | `return true;` | 把"真"交出去——这是占位，你要改的就是它 |
| 9 | `}` | check 结束 |
| 10 | `public static void main(String[] args) {` | 程序从这里开始跑；这一串是固定格式，先照抄 |
| 11 | `Budget b = new Budget();` | 印一张新表，起名 b，初始 1000/0/0 |

```java
boolean check() {
```

一、这个项目到底是干嘛的

一句话：一个团队有一笔经费，谁要花钱得先申请，老师批准，财务登记实际花了多少；系统保证每一分钱都对得上。

一个故事（就是你程序里正在跑的那四行）：实验室有 1000 元，小林要买传感器，预算 600。
1. 他在系统里填申请：用途、金额 600，保存成草稿。钱一分没动。
2. 点提交：系统先把 600 从"可用"挪到"冻结"（预留，别人不能再花）。这时 400 / 600 / 0。
3. 老师说最多批 500，批准 500。多留的 100 立刻退回可用。这时 500 / 500 / 0。
4. 东西买完实际花了 460，财务结算 460。冻结清掉，460 记入已使用，没花掉的 40 回可用。这时 540 / 0 / 460。

从头到尾 1000 = 540 + 0 + 460。这就是整个项目唯一一条硬规则。

谁在用：成员（填申请、提交、取消自己的）、老师（批准、减额批准、拒绝）、财务（登记实际花费）、管理员（建项目、分配人，基础版可以先不管）。

一张申请单的一生：草稿 → 待审批 → 已批准 → 已结算；半路分叉：待审批 → 已拒绝，待审批或已批准 → 已取消。

系统分三块：数据（项目、成员、申请单）、规则（后端：谁能做什么、状态能不能改、钱怎么动、出错当没发生）、页面（前端：填单、待审批列表、待结算列表、经费卡片）。你写的 `Budget` 就是"钱怎么动"的最小内核。


要加的东西：
1. 两个字段：`int applying = 0;`（这张单要多少钱）、`int approved = 0;`（批了多少）。
2. `submit` 里记下 `applying = amount;`。
3. `approve(int amount)`：`amount <= 0` 或 `amount > applying` 时返回 false；否则算差额 `applying - amount`，差额从冻结退回可用，再记 `approved = amount`。
4. `settle(int actual)`：`actual < 0` 或 `actual > approved` 时返回 false；否则冻结减掉 `approved`、已使用加上 `actual`、可用加上 `approved - actual`。

关键一句：批准后冻结里只留被批准的额度，多留的立刻回可用——退的是"差额"，不是"批准的额度"。

一、"启动并监听"拆开讲

启动：`./mvnw spring-boot:run` 最终做的事是起一个 java 进程，里面跑 Spring。这个进程先扫描你的类，把 `@GetMapping("/api/ping")` 这类标签收集成一张"地址 → 方法"的表，然后启动内嵌的 Tomcat 服务器。日志里那行 `Started BackendApplication in x seconds` 就是"进程起来了、表建好了"。

监听：Tomcat 启动后向操作系统申请占用 8080 端口，操作系统把"发到本机 8080 的请求"交给它。所以"监听 8080"= 这个进程守在 8080 这扇门后面，谁敲这扇门都由它先接。

端口是什么：一台电脑一个 IP，但要同时跑很多程序，靠端口区分。IP 像大楼地址，端口像房间号。8080 是开发常用端口，因为 80 是系统端口、需要管理员权限。

为什么改代码要重启：路由表是启动时建的，新写的类不在表里。`Ctrl+C` 结束进程，端口释放；不结束就再启动会报 `Port 8080 was already in use`。

二、一次请求怎么走

```
浏览器地址栏 http://localhost:8080/api/ping
  → 本机回环地址 127.0.0.1，端口 8080
  → 监听这个端口的 java 进程（Tomcat）接住
  → Spring 在路由表里查 /api/ping
  → 找到 PingController.ping()
  → 返回 "pong"
  → HTTP 200 + 响应体 pong
  → 浏览器显示 pong
```

查不到就是 404：请求到了服务器，但没有地址对得上。

三、五条"学到"逐条展开

1. 工程结构
   - `pom.xml`：依赖清单 + 版本 + 打包方式，Maven 照它去下载 jar。
   - `src/main/java`：源码，包的层级对应目录。
   - `src/main/resources`：配置，`application.properties` 就在这。
   - `src/test/java`：测试代码。
   - `target/`：编译产物，每次构建重新生成，所以不提交（`.gitignore` 已经忽略）。

2. `mvnw` 为什么等于"自带 Maven"
   - `mvnw` 是个脚本，配 `.mvn/wrapper/maven-wrapper.properties` 里写的版本。
   - 第一次运行会把那个版本的 Maven 下到 `~/.m2/wrapper`，依赖下到 `~/.m2/repository`。
   - 所以不用装 Maven，但需要网络；换台电脑只要带这个脚本就能复现同一版本。

3. 内嵌 Tomcat
   - 老做法：自己装 Tomcat，把 war 包丢进它的目录，由外部服务器加载你的代码。
   - Spring Boot：Tomcat 只是 pom 里的一个依赖，`SpringApplication.run(...)` 在 main 里把它拉起来。所以一个 `java -jar` 就能跑，这是它能独立部署的原因。

4. 注解与"为什么不用 new"
   - `@RestController`、`@GetMapping` 是贴在类和方法上的标签。
   - Spring 启动时扫描这些标签，生成路由表，并自己创建 `PingController` 的对象（叫 bean）。
   - 请求来时，Tomcat 交给 Spring 的 DispatcherServlet，它查表、调用对应方法、把返回值写进响应体。
   - 你不用 new，因为对象的生命周期归容器管。

5. Boot 4 与 3.x 的差别
   - 3.x：`spring-boot-starter-web`。
   - 4.x：`spring-boot-starter-webmvc`，H2 控制台拆成 `spring-boot-h2console`。
   - 照抄 3.x 教程的 pom 会报依赖解析失败，这是版本差异，不是你写错了。

6. 404 的 JSON 是什么
   - 那是 Spring 默认的错误响应（`timestamp/status/error/path`）。
   - 它证明"服务活着、只是没有这个地址"。
   - 如果服务没起来，浏览器根本连不上，显示的是"无法访问此网站"，两者很好区分。
