# 10 项目通读（答辩前扫一遍）

这份文档用大白话讲清：项目做什么、钱怎么变、代码分几层、演示怎么走、被问了怎么答。

## 一、一句话说清

一个项目有 1000 元，成员要花钱先申请，老师批准多少，财务登记实际花多少；系统保证**总预算 = 可用 + 冻结 + 已使用**，任何操作都不能让这个等式失衡、不能出现负数。

## 二、三个角色

| 角色 | 账号 | 能做什么 |
|---|---|---|
| 成员 | member1 | 新建、提交、取消**自己**的申请 |
| 老师 | teacher1 | 批准、拒绝**别人**（同项目）的申请 |
| 财务 | finance1 | 结算已批准的申请 |

密码都是 `123456`（演示用明文）。

## 三、申请单的六个状态

```
草稿 DRAFT ─提交→ 待审批 PENDING_L1 ─批准→ 已批准 APPROVED ─结算→ 已结算 SETTLED
                        │                        │
                        ├拒绝→ 已拒绝 REJECTED    └取消→ 已取消 CANCELED
                        └取消→ 已取消 CANCELED
```

## 四、钱怎么变（心脏）

| 动作 | 可用 | 冻结 | 已使用 |
|---|---|---|---|
| 新建草稿 | 不变 | 不变 | 不变 |
| 提交 | 减申请金额 | 加申请金额 | 不变 |
| 批准（批 500、申请 600） | 加差额 100 | 减差额 100 | 不变 |
| 拒绝 | 加回申请金额 | 减掉申请金额 | 不变 |
| 取消 | 加回剩余冻结 | 减掉剩余冻结 | 不变 |
| 结算（实际 460、批 500） | 加回 40 | 清零 | 加 460 |

背这一个例子就够：

```
起点      1000 / 0 / 0
提交 600   400 / 600 / 0      钱从"能花"变成"先留出来"
批准 500   500 / 500 / 0      只批 500，多留的 100 退回可用
结算 460   540 / 0 / 460      冻结清零，460 记已花，剩 40 回可用
```

每一步都是 `1000 = 540 + 0 + 460`。

## 五、数据库里有什么（够用版）

三张表：

| 表 | 存什么 |
|---|---|
| 项目表 | 这个项目有多少钱（总预算、可用、冻结、已花） |
| 申请表 | 每张单子：谁申请的、买什么、多少钱、批了多少、花了多少、什么状态 |
| 账号表 | 三个账号和角色 |

三句能说的话：

1. "数据存在数据库里，三张表：项目、申请、账号。"
2. "页面上的数字和表格都是从这里读出来的，不是写死的。"
3. "程序关掉再打开数据还在，因为它存在一个文件里。"

## 六、代码分几层

```
com.ianchen.backend
├── 启动类 BackendApplication
├── controller   收请求（谁访问了哪个地址）
├── service      业务规则（钱怎么算、能不能做）
├── repository   读写数据库
├── entity       和表对应的类
├── dto          接前端传来的 JSON
└── exception    统一错误格式
```

一句话职责：**controller 只是前台，service 才是算账的，repository 是取数据的管理员。**

## 七、点一次"提交"发生了什么（六步）

1. 浏览器发请求 `POST /api/applications/1/submit`，带登录 token
2. Vite 把 `/api` 代理到 8080
3. 控制器用 token 换出"当前用户"
4. `BudgetService.submit` 检查：是不是成员、是不是自己的单、是不是草稿、金额是否合法、钱够不够
5. 改两处：项目可用减少、冻结增加；申请状态改 `PENDING_L1`
6. 返回结果，页面重新拉数据，数字更新

## 八、演示脚本（3 分钟）

1. 开场一句话："这是经费申请系统，成员申请、老师审批、财务结算，核心是保证钱的总数不变。"
2. `member1` 登录 → 显示 1000/0/0
3. 点提交 → 400/600/0，"钱从能花变成先留出来"
4. 退出，`teacher1` 登录 → 批准 500 → 500/500/0，"只批 500，多留的退回可用"
5. 退出，`finance1` 登录 → 结算 460 → 540/0/460，"冻结清零，460 记已花"
6. 补一句："成员看不到批准按钮，老师批不了自己的单，后端会拦。"
7. 收尾："代码分 controller / service / repository / entity，写操作都加了事务，失败不会只改一半。"

## 九、被问住时怎么说

- 数据库底层（索引、连接池）："这块是项目里现学的，我能讲清三张表和读写，更深的还没学。"
- 事务原理："我知道它保证要么全成、要么全不成，验证方式是故意让它报错，看数据有没有改一半。"
- 没做的功能（多项目、分页）："没做，README 里写了未完成项。"

**原则：不会就说不会，别编。**
