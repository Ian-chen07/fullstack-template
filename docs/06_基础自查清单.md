## 业务

- [x] 草稿不占钱，提交才冻结；经费不足仍保留草稿。
  - 新建草稿后金额不变；余额不足时接口返回 400 且数据不变（用 9999 元测过）。
- [x] 用途必填，申请金额大于零且最多两位小数。
  - 2026-11-21 实测：`approve?amount=5.001` 返回 400“批准金额最多两位小数”；用途为空返回“请填写用途”。
- [x] 提交后不能直接改原始信息。
  - 没有提供任何编辑接口，提交后金额、用途无法通过接口修改。
- [x] 批准不超申请，减额差额立即恢复。
  - 实测：600 元申请批 500，项目从 400/600 变为 500/500，差额 100 立即回到可用。
- [x] 拒绝、取消只释放剩余冻结，不能重复释放。
  - 2026-11-21 实测：待审批 50 元被拒绝后回到 1000；已批准 5 元取消后只释放 5，账目回到原样；缺原因时返回 400。
- [x] 结算允许零元，不超过批准金额；结束后不能重复办理。
  - `actual = 0` 允许；超过批准额返回 400；已结算再结算返回 400 且数据不变。
- [x] 每步都满足“总预算 = 可用 + 冻结 + 已使用”，各项非负。
  - 实测四步：1000/0/0 → 400/600/0 → 500/500/0 → 540/0/460，每步相加都等于 1000。
- [ ] 数据库操作失败，没有只改一半的数据。
  - 部分完成：六个写方法都加了 `@Transactional`，但**没有实际制造过数据库中途失败来验证回滚**，不能算已验证。
