# Java 账本练习（块 1–3）

## 块 1：账本与守恒

**目的**：整个项目只有一条规则——总预算 = 可用 + 冻结 + 已使用。先把这条规则写成能跑的程序，接口和页面才有意义。

**做了什么**：`Budget.java` 三个金额字段，`check()` 判断账平不平，`main` 打印初始状态。

**怎么验证**：`cd 学习记录/java && javac Budget.java && java Budget`，输出 `1000/0/0` 和 `守恒: true`。

**学到**：

- 代码必须装在一个 `class` 里；字段是数据，方法是操作，`main` 是入口。
- 字段属于对象：`new` 出一份，外面用 `b.available` 访问，方法内部直接写 `available`。
- `boolean` + `if` + `return`；`javac` 编译、`java` 运行；public 类名必须等于文件名。

**没懂 / 待学**：`public`、`static`、`void`、`String[] args` 的确切含义。

## 块 2：提交 = 冻结

**目的**：提交要把钱从"可用"挪到"冻结"；失败时一分钱都不许动。这是后面数据库事务要保证的东西，先在内存里练。

**做了什么**：`submit(int amount)`——金额 ≤ 0 或超过可用时直接 `return false`；成功则 `available` 减、`frozen` 加，`return true`。

**怎么验证**：

```
1000/0/0
守恒: true
提交 600: true
400/600/0
守恒: true
提交 9999: false
400/600/0
守恒: true
```

关键是最后三行：提交 9999 失败之后仍然是 `400/600/0`，账没动。

**学到**：

- `if` 里用 `||` 把两个判断合成一条。
- 提前 `return` 就是"这一趟不办了"，后面的行不执行。
- `available = available - amount;` 才是把值存回去；写成 `available - amount;` 只是算完丢掉。
- 方法返回 `boolean`，调用方才知道成不成功。

**没懂 / 待学**：`static` 与对象的关系；为什么金额不能长期用 `int` 元（下一步换 `BigDecimal` 处理两位小数）。

## 块 3：批准与结算（11.3）

**目的**：补上剩下两条业务规则——批准时退差额，结算时把冻结变成已使用。

**做了什么**：

- 加两个字段：`applying`（申请金额，提交成功时写入）、`approved`（批准金额，批准时写入）。
- `approve(amount)`：金额必须大于 0 且不超过申请额；`diff = applying - amount` 从冻结退回可用，再记录 `approved`。
- `settle(actual)`：实际花费必须在 0 到批准额之间；冻结减 `approved`、已使用加 `actual`、可用加 `approved - actual`。

**怎么验证**：14 行输出，最后五行为

```
批准 500: true
500/500/0
结算 460: true
540/0/460
守恒: true
```

文档里 1000 元那个例子四步全部走通：`1000/0/0` → `400/600/0` → `500/500/0` → `540/0/460`。

**学到**：

- 参数只活一次调用，字段才是对象的记忆，所以要 `approved = amount;` 把批准额记下来。
- 批准退的是差额（申请额 − 批准额），不是批准额本身。
- 结算三个动作：冻结减批准额、已使用加实际额、可用加剩余。
- `available = approved - actual` 会覆盖旧值，正确的是 `available += approved - actual`。

**踩过的坑**：

- `used = approved;`：批准额一直是 0，结算被 `actual > approved` 挡掉。
- 方法写进另一个方法里、少分号、`=` 与 `+=` 混淆，都被编译器和 `check()` 抓住了。

**没懂 / 待学**：申请状态（草稿 / 待审批 / 已批准 / 已结算）还没做；金额仍是整数元，后面换 `BigDecimal`。
